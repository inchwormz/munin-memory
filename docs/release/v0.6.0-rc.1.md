# Munin 0.6.0-rc.1 Local Release Candidate

Status: approval-ready local candidate. `tag: not created; approval required`.
Nothing in this candidate record authorizes a push, tag, GitHub release,
crates.io publish, marketplace submission, production install, or deletion of
real user data.

## Product change

- Native Codex and Claude plugin-manager lifecycle with reversible migration,
  bounded session-start refresh, isolated rollback, and real-host checks.
- Six strict read-only MCP tools with typed schemas, provenance, freshness,
  sensitivity, redaction, warnings, and coverage receipts.
- Fast read-only Doctor, executable inspect/export/retention/forget controls,
  and public security, threat, incident, and data-lifecycle contracts.
- Warnings-denied clippy, Rust 1.78 MSRV, RustSec/license, old-schema migration,
  package-content, and version/hash provenance gates.

## Candidate identity

The authoritative pre-release receipt is produced after the candidate commit:

```powershell
pwsh -NoProfile -File .\scripts\munin-provenance-check.ps1 `
  -MuninBin <fresh-binary> -RepoRoot . -RequireCandidate -Format json
```

It must show one `0.6.0-rc.1` value for Cargo, binary, Claude plugin, Codex
plugin, and MCP server; hash the two marketplaces, two plugin manifests, two MCP
declarations, lockfile, and binary; and report that no tag exists.

## Required evidence before approval

- Fresh format, clippy, Rust 1.78, full Windows GNU tests, resolver, package,
  strict Claude validation, licenses/advisories, migration, and provenance.
- Isolated native Codex/Claude install, rollback, retrieval, and uninstall.
- Isolated privacy lifecycle with export hash verification and unrelated-source
  sentinels preserved.
- Real compiled-corpus Doctor timing under two seconds without import mutation.

GitHub-hosted CI remains an external check until the branch is pushed. Host
marketplace publication, crates.io publication, and the release tag are explicit
operator approval boundaries.
